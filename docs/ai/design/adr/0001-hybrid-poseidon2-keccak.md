# ADR-0001: Hybrid Poseidon2 + Keccak-256 hash boundary

## Status

Accepted for protocol v1. Independent cryptography review `91cfa5ee` accepted this boundary.
Product approved T0.2 on 2026-08-17.

## Context

Haze must produce the same commitments in Circom (BN254) and the same wallet/envelope hashes on Avalanche C-Chain. Poseidon2 is cheap in-circuit. Keccak-256 is native to the EVM and EIP-712.

## Decision

- Use Poseidon2 width-3, rate 2, capacity 1, s-box \(x^5\), 8 full + 56 partial rounds for every in-circuit digest (note key, encryption-key hash, note commitment, nullifier, Merkle node, policy leaves, audit-data commitment).
- Place a domain tag in the sponge capacity lane. Absorb with pad10*. Reject a zero digest.
- Use Keccak-256 for EIP-712 type/struct/domain hashes, HPKE envelope ciphertext hashes, and Haze address checksums.
- Never reduce a `bytes32` identifier modulo \(r\) except for reviewed domain constants derived from a Keccak tag.

## Consequences

Cross-language vectors pin both families. A Solidity or TypeScript harness can recompute every Keccak value. Poseidon values are generated by the Rust reference (`zkhash`) and independently reproduced by Circom 2.2.3 gadgets in T1.1.
