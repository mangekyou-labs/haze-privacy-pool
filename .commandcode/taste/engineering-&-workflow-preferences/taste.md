# Engineering & Workflow Preferences
- Prefers strict Test-Driven Development: write the failing (red) test first, then the minimum code (green), then refactor — and verify each step with actual command output. Confidence: 0.95
- Requires verification with fresh command output — never claims lint/tests/green without running and showing the actual command results (e.g. `node --test ...`, `git diff --check`, explicit pass/fail counts). Confidence: 0.9
- Keeps lifecycle documentation (planning / design / implementation / testing) in lockstep as work progresses, updating the relevant docs after each unit of work rather than only at the end. Confidence: 0.9
- Prefers reusing existing modules/helpers over rewriting — copies unchanged, wraps or extends existing code (e.g. reusing ptau/phase2/export planners) and avoids duplicating a pattern that a shared helper already covers. Confidence: 0.85
- Works in an isolated feature worktree and refuses to touch a dirty main checkout; copies source material from main read-only. Confidence: 0.85
- Uses structured, detailed execution plans — tables for task tracking, checkboxes, and clear lists of hard non-goals — and records progress in project docs rather than relying on an external task tracker. Confidence: 0.8
- Respects explicit hard non-goals and operator boundaries: does not run live ceremonies, deploy, broadcast, commit artifacts (zkeys/ptau/secrets), or mark operator-gated milestones complete. Stops at external/operator boundaries and reports them as blocked. Confidence: 0.9
- Diagnoses root cause and confirms the actual data flow before writing tests or fixes — plans include a "why a blind rerun will fail" analysis, and code paths are read/verified before any change is made. Confidence: 0.8
- Preserves historical evidence/artifacts by copying them aside as dated snapshots before any overwrite; never destroys prior run outputs (manifests, screenshots) in place. Confidence: 0.8
- Prefers the smallest compatible change when fixing: keeps response/API shapes and unrelated behavior (e.g. HPKE AAD bindings, field sets) untouched, and checks downstream consumers before reshaping output. Confidence: 0.75
- Tooling: prefers the `playwright-cli` skill over Playwright MCP for manual CLI/browser recovery. Confidence: 0.85
- Gates implementation behind a correct, approved design: when the current design is wrong relative to requirements/reference IA, stops in the design phase and revises design, then planning, then implementation — rather than shipping chrome patches that merely prop up a flawed design. Confidence: 0.9
- Keeps protocol/debug implementation details out of user-facing product chrome: no chain-ids, KEYS_MISSING, debug status lines, or internal field names in the UI; failures surface as human-readable errors (e.g. "Proof failed — retry"). Confidence: 0.8
- Keeps heavy/stateful computation (e.g. Groth16 proving, local vault) in the client rather than moving it to serverless/host; Vercel/host handles only what fits (quotes, membership) while prove/sign/send stay on-device. Confidence: 0.75
- Web-app shell/session: prefers a single persistent client provider with silent session resume (no reconnect on navigation, no `location.reload()` after connect, no state lost on tab changes) over a per-route client that re-initializes each navigation. Confidence: 0.75
- Labels operator-gated milestones as "local complete / live blocked" and keeps their planning checkboxes `- [ ]` (docs are the tracker); flips a box `[x]` only once its validation is purely local/topological and needs no live RPC — deliberately not self-celebrating unfinished work. Confidence: 0.8
- Places QA/browser-walk artifacts (screenshots) and build outputs into a gitignored `output/` dir and verifies with `git check-ignore` that generated artifacts don't pollute the working tree before finishing; treats leftover untracked build/screenshot files as cleanup items. Confidence: 0.7
- Runs browser/UI QA against the production build (`next build` + `next start`) rather than the dev server when `next dev` is unstable/broken, and documents the dev-server quirk in docs rather than blocking on it. Confidence: 0.6
- Proves a test genuinely fails by reverting the production hunk (revert → fail → restore → pass) as the required reversal step in every red/green cycle, rather than trusting the test on face value. Confidence: 0.8
- Applies bounded timeouts (e.g. `AbortSignal.timeout(...)`) to upstream/BFF fetches so a hung downstream service fail-opens to a degraded state or error instead of blocking the UI indefinitely. Confidence: 0.75
- Uses a fixed visual system, not a clone of a reference app: IBM Plex Sans/Mono, `tabular-nums`, a 4/8/12 spacing scale, no Tailwind/shadcn, and a branded token set (alpine-volcanic). Confidence: 0.8
- Deploys production as a Vercel prebuilt build (`vercel pull` → `vercel build --prod` → `vercel deploy --prebuilt --prod -y`) from the worktree `haze/` dir, without git-pushing to main. Confidence: 0.75
